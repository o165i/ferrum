# История разработки FERRUM

Документ фиксирует основные этапы разработки, используемые технологии и способ проверки. Новые записи добавляются при подготовке каждой следующей ветки.

## Интеграция дизайна

- Прототип интерфейса перенесён в структуру Next.js и разделён на страницы и компоненты.
- Главная страница получила блоки Recent и Popular, а полный список товаров перенесён в каталог.
- Удалены временные подписи и элементы старой статической заглушки.
- Использовано: Next.js, React, TypeScript и CSS Modules.

## Каталог и API товаров

- Каталог подключён к серверному API и тестовой базе товаров.
- Добавлена постраничная загрузка товаров без поиска и сложной сортировки.
- Сервер проверяет доступность и актуальную стоимость товара.
- Использовано: Next.js Route Handlers, Prisma и PostgreSQL в Neon.

## Авторизация и личный кабинет

- Добавлены регистрация, вход, выход и защищённая страница аккаунта.
- Пароли сохраняются в виде bcrypt-хешей, сессия подписывается и имеет ограниченный срок действия.
- Использовано: NextAuth, JWT, bcrypt и Zod.

## Корзина и оформление заказа

- Добавлена локальная корзина с размером и количеством товара.
- Оформление доступно авторизованным пользователям.
- Заказ создаётся только после серверной проверки цены, наличия и остатка; изменение остатков выполняется транзакционно.
- Добавлены история заказов и страница успешного оформления.

## Панель администратора

- Добавлен защищённый раздел для пользователей с ролью ADMIN.
- Реализованы создание, редактирование, включение и выключение товаров.
- Реализовано подтверждение и отмена заказов с безопасным восстановлением остатка при отмене.
- Проверены ограничения доступа для обычного пользователя.

## Публикация

- Приложение опубликовано на Vercel.
- PostgreSQL размещён в Neon; секреты передаются приложению через защищённые переменные окружения Vercel.
- Конфигурация GitLab CI в YAML удалена по запросу владельца проекта из-за ограничения GitLab Identity Verification. Старые неуспешные запуски остались только в истории GitLab.

## Ветка `feature/checkout-payment-methods`

### Что сделано

- Оплата при получении удалена из пользовательского оформления и серверной валидации новых заказов.
- Банковский перевод сохранён как рабочий способ оплаты; заказ получает статус `PENDING`.
- На странице подтверждения показываются тестовые банковские реквизиты, сумма и номер заказа как назначение платежа.
- Добавлен подготовленный вариант PayPal в EUR. До получения данных PayPal Business/Developer кнопка не создаёт заказ и не проводит платёж.
- Apple Pay сознательно не подключался: он требует отдельного платёжного провайдера и настройки продавца/домена.

### Как реализовано

- Допустимый способ обычного создания заказа ограничен значением `BANK_TRANSFER` через Zod.
- В Prisma добавлен будущий вариант `PAYPAL`; старое значение `CASH_ON_DELIVERY` сохранено только внутри типа базы для чтения исторических заказов.
- Реквизиты вынесены в серверную конфигурацию и могут быть заменены переменными окружения.
- Для PayPal подготовлены переменные окружения Client ID, Client Secret и режим sandbox.

### Что потребуется для завершения PayPal

- Получить Client ID и Client Secret приложения PayPal Business/Developer.
- Реализовать серверные вызовы PayPal Orders API для создания и подтверждения платежа.
- Подключить официальный PayPal JavaScript SDK и проверить оплату сначала в sandbox.
- Сохранять заказ только после подтверждённого результата PayPal, чтобы неоплаченные заказы не уменьшали остатки.

### Проверка

- Серверная схема принимает банковский перевод.
- Оплата при получении и прямое создание неоплаченного PayPal-заказа отклоняются.
- Перед публикацией выполняются тесты, проверка кода и production-сборка.

## Ветка `feature/readable-typography`

### Что сделано

- Весь основной интерфейс переведён на Geist Sans, а короткие технические метки — на Geist Mono.
- Увеличены размеры и насыщенность навигации, категорий, кнопок, подписей, форм, цен и поясняющего текста.
- Повышен контраст вторичного текста на тёмном фоне.
- Без изменений оставлены логотип `FERRUM`, крупные декоративные заголовки и названия товаров.

### Как реализовано

- Шрифты Geist подключены локально через официальный пакет и Next.js, без внешнего запроса к сервису шрифтов.
- Общие переменные типографики настроены централизованно, а размеры уточнены в CSS Modules отдельных страниц и компонентов.
- Изменения охватывают главную страницу, каталог, корзину, checkout, авторизацию, аккаунт и панель администратора.

### Проверка

- Выполнены тесты, линтер и production-сборка.
- Главная страница и checkout проверяются визуально в браузере до публикации.
- Production-переменные Neon/Auth сохранены в защищённых настройках Vercel, а локальные `.env`-файлы исключены из загрузки при следующих публикациях.
